# Kyntral governance

Kyntral is community-contributable and canonically stewarded.

## Community rights

Contributors may:

- open issues and discussions
- propose Kyntral Enhancement Proposals (KEPs)
- submit pull requests
- build compatible adapters and capabilities
- fork code subject to the applicable software licenses
- review specifications and conformance behavior

## Canonical authority

The canonical project retains final authority over:

- protocol releases and version numbers
- canonical repository merges
- official registry certification
- production signing infrastructure
- official application releases
- Kyntral trademarks and brand identity
- security release decisions
- commercial licensing of BUSL-covered components

Current canonical steward: **Deonte Watts (@DeontewattsV1)**.

## KEP requirement

A KEP is required for material changes to:

- protocol schemas
- trust or authorization semantics
- privacy boundary
- cryptographic identity/signing rules
- risk classes
- extension/registry trust model
- backward compatibility guarantees

## Contribution licensing

External code must not be merged until the project's contributor-license
process is finalized and the contributor has accepted the then-current terms.
Issues, design proposals, documentation suggestions, and review feedback remain
welcome in the meantime.

## No bypass

Maintainers cannot waive mandatory security/conformance checks merely to speed a release.
